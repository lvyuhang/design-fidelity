# 蓝湖 MCP → Flutter 视觉还原自动化工作流

## 目标

视觉还原必须以可重复的证据和门禁完成。运行成功、组件尺寸正确或整页 MAE 较低，都不能单独作为视觉验收结论。每个交付候选都要通过结构、可见几何、颜色、字体和像素回归检查。

## 流水线

1. **固定源证据**：保存蓝湖 `snapshot_id`、`resolved_version`、完整节点 JSON、原始 4× 参考图和切图 SHA-256。源版本改变时创建新基线，不覆盖旧基线。
2. **生成视觉契约**：用蓝湖节点 ID 描述关键区域、可见元素和组内关系。ROI 从节点 `bounds` 自动生成，不在检测脚本中手写坐标。
3. **生成 Flutter**：所有关键 Widget 保留源节点 ID 或稳定 Key；设计画布为 375px 时使用固定 375 逻辑像素，不随桌面预览拉伸。切图按导出画框放置，禁止按不透明像素自动裁边。
4. **目标环境渲染**：在交付用渲染器中按设计画布和固定 DPR 截图。Flutter 测试渲染与 Web 浏览器分别建基线，不互相代替；截图前必须确认字体文件已经加载且中文字形覆盖完整。
5. **自动门禁**：先校验画布、资源哈希和节点几何，再运行 `tools/visual_fidelity_gate.py`。脚本比较关键元素的可见边界、中心、尺寸、墨迹面积、组内中心线关系，并计算关键区域 MAE/P95。
6. **生成诊断产物**：每个候选生成 JSON、HTML 和对齐标注图。绿色框代表原稿可见主体，粉色框代表实现；报告直接列出超阈值的轴和像素数。
7. **阻断与修正**：任一 blocking 规则失败时命令返回 1，候选不能替换基线。修正只能针对报告中的失败规则；新一轮重新渲染、重新测量并保留上一轮证据。

## 为什么能规避这次问题

“平台能力介绍”一行由两个节点组成：位图徽章 `14D9E6CC-37AE-4AB2-9258-2D4D87DF2351` 与标题 `A2341762-66D3-4BEF-A1FA-632A86E77426`。位图含透明留白，因此仅比较 34×34 外框会产生假通过。视觉契约分别提取徽章的金色可见像素与标题的深色字形像素，检查：

- 各自的可见中心相对原稿偏移是否 ≤ 1px；
- 可见宽高是否偏差 ≤ 1.5px；
- 两者中心线差值相对原稿是否偏差 ≤ 0.75px；
- 平台能力区域 MAE/P95 是否超过回归阈值。

因此，布局框相同但图标透明边距、缩放或文字行高导致的肉眼错位会直接失败。

本地诊断当前失败候选时可临时增加 `--allow-fail` 以生成报告；CI 不得使用该参数。

## 契约维护原则

- 关键业务层级至少包含一个区域门禁；标题行、按钮内容、卡片图文行至少包含一个关系门禁。
- 阈值使用逻辑像素，依据目标平台的抗锯齿波动设定。位置通常 0.5–1px，尺寸 1–1.5px；文字像素指标需按渲染器单独设定。
- 对照片等不可控内容使用遮罩，但头像、图标、文字、边框和间距仍需独立检测。不得用大面积背景均值稀释局部错误。
- 切换字体、图片缩放、设备像素比或渲染器时必须触发全量视觉回归。
- 只有相同源快照、相同渲染环境、相同裁剪和相同密度的结果才能比较。

## CI 门禁顺序

```text
MCP 证据完整性
  → 资源 SHA-256 / 字体覆盖
  → Flutter 静态分析与组件测试
  → 固定画布 4× 截图
  → 可见几何与组内关系
  → 关键颜色与区域像素回归
  → Web 真机渲染抽检
  → 允许更新视觉基线
```

像素门禁负责自动阻断确定性错误；交互态、动效和内容语义仍需测试覆盖。人工核对用于发现并沉淀新规则，不能作为每次交付都依赖的补救步骤。
