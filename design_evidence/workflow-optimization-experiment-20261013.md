## 调用与 token 记录

新页面取证共 12 次 MCP 相关调用：9 次蓝湖工具调用和 3 次 MCP 资源读取。正式缓存回放没有 MCP 调用。

截至 14:12:08，新页面阶段处理 16,806,953 个原始上下文 token，其中输入缓存命中率 98.62%；扣除缓存输入后，新增输入 231,299、输出 46,502，合计 **277,801 个有效新增 token**。推理 token 12,370 已包含在输出统计中。

整个两轮实验处理 23,085,757 个原始上下文 token，输入缓存命中率 98.35%；有效新增输入与输出合计 447,933。

新页面完成后又对共享的 `1备份 34` 运行回归门禁，16.25 秒通过，状态仍为 `PASS_WITH_EXCLUSIONS`，说明公共组件修正没有破坏已交付页面。

## 结论与下一步

当前优化保持了最终品质，并把新页面耗时降低约 29%，但仍应继续优化。主要成本已经从视觉修正转移到取证落盘和契约准备。

下一轮应固定以下动作：

1. 在取证脚本内完成分页合并和资源流式落盘，取消终端承载大 JSON/ZIP 的路径。
2. 在首轮渲染前收集新页全部字符并更新原字体子集，避免字体预检后返工。
3. 为同类页面复用契约模板，只生成新增节点、素材和关系检查；公共节点继承已验证规则。
4. 首轮先跑新增 ROI 门禁，修正通过后只跑一次完整门禁。
5. 将 Web release 构建放到最终交付阶段；开发迭代只运行 1.8 秒左右的渲染和视觉门禁。
6. 新页面使用独立短任务或压缩证据包，减少长线程上下文造成的 token 重复读取。

下一张同复杂度页面的目标是首次实现 **12–15 分钟**，正式回放保持 **20 秒内**，有效新增 token 控制在 **15 万以内**。
