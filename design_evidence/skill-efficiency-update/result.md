# 流程优化落地结果

更新：lanhu-design-fidelity 2.6.0。目标为减少重复工作与返工，耗时允许随页面复杂度变化。

## 已落地

1. 统一版本：项目可分发包原为 2.0.0，安装包原为 2.5.0；已备份两个版本并以 2.5.0 为基线更新。
2. 新增 `preflight.py`：编码前定位原始文字样式缺口；渲染前检查契约、源身份、文件哈希、字体 cmap、参考尺寸和资产解码。仅有索引不视为样式证据完整。
3. 新增 `run_flutter.py`：复用一个运行器串联预检、真实渲染、视觉门禁、可选静态检查和最终构建。契约只读；各轮输出独立。保留完整日志，仅回传失败摘要。
4. 原型 `tools/fidelity_fastlane.py` 已改为兼容入口，避免两套逻辑漂移。
5. 高效执行规则进入 Skill：固定证据复用、工具层落盘、避免大段日志回显、先补字再渲染、只在交付阶段构建、按复杂度记录全过程耗时。不设置硬性速度承诺。

## 结论边界

已证明：相同检查可由可复用工具执行；原有 42 项回归保留；缺字和索引缺样式可更早发现；工具摘要不会替代完整证据。

未证明：首次不同布局页面平均能节省多少时间或 token。下一次实际页面任务使用 2.6.0，自然记录取证、实现、修正、验证和交付耗时，再比较返工原因。不能将 2–4 秒检查链路当成首次页面实现时长，也不能把输出缓存 token 当作免费。
