# 流程问题定义与交付门禁

高保真失败通常不是“最后少调几个像素”，而是更早的流程没有闭环。以下问题按发生顺序定义；后序视觉循环不能替代前序门禁。

## 五类流程问题

1. **源覆盖缺口**：素材下载成功率被误当成页面完整性。可见文本、无 `asset_id` 的位图/矢量、低透明装饰和带效果的父节点仍可能遗漏。
2. **证据精度缺口**：overview、节点摘要或旧缓存只有 bounds/text，缺少 `raw_style`、字体、渐变、阴影、蒙版或裁剪。此时根据截图猜值会把取证问题变成人工调参问题。
3. **坐标闭环缺口**：为修一个子节点而移动父容器，随后再用局部偏移补偿。局部可能对齐，但父级尺寸、裁剪、装饰和组件间距会漂移。
4. **契约覆盖缺口**：整页 MAE 或大区域指标改善，却没有独立检查小面积、低透明度或父级视觉效果。未被契约描述的内容无法被门禁保护。
5. **停止条件缺口**：把 2–3 轮效率目标当成交付上限，或把 legacy diagnostic 当成当前实现的验收。轮数不能覆盖质量条件。

## 编码前门禁

先准备以下信息；缺证据仅阻塞受影响节点，可同时实现证据齐全的区域。所有未处置项必须在正式验收前闭环：

1. 固定 `snapshot_id`、`resolved_version`、画布、参考图和完整分页节点数。
2. 为每个可见清单节点记录一种处置：`original_asset`、`native_exact`、`render_fallback`、`missing_asset_placeholder` 或 `excluded_with_reason`。不得存在 `pending`、`unaccounted` 或静默遗漏。
3. 对以下高风险节点保存定向 inspect 证据，而不只保存摘要：渐变、阴影、模糊、蒙版、裁剪、透明叠层、特殊字体、无 `asset_id` 位图、复杂矢量、带视觉效果的父节点。
4. `raw_style` 不足时先定向补取。复杂节点优先原始导出或源节点 `render_fallback`；仍无法取得时按源画框占位并登记排除，不根据截图仿造。
5. 字体不可用时不能悄悄替换。业务文字补字体；仅用于装饰的特殊字形优先源渲染回退，否则占位并说明。

资源数量只用于验证下载，不作为节点覆盖率。`11/11 assets` 不能替代 `0 unaccounted visible nodes`。

执行约束由 `source_requirements.py`、契约编译器和正式门禁共同校验；字段及支持范围见 [执行约束与迁移](preparation.md#执行约束与迁移29)。代码符号、素材语义和最终视觉复查仍需执行者确认，字段存在不证明实现正确。

## 契约门禁

- 新实现、重新实现或当前版本修复必须使用 `schema_version: 2` 且 `status: ready` 的冻结契约。旧 v1 只能回放历史测量；只要快照仍可 inspect，就必须先升级证据和 v2 契约，不能用 diagnostic 结果交付当前实现。
- coverage 必须包含可见叶节点和带阴影、渐变、蒙版、裁剪或透明叠层的父节点。
- 独立装饰、低透明数字、星光、下划线和小图标使用独立 blocking feature；不能由整页 region 代替。
- 渐变至少检查起点、中段、终点；阴影在实体边缘、峰值和衰减外沿检查。父子边距和组件间距使用 relation 或精确几何检查。
- 最终并列图发现契约未捕获的明显差异时，先新增检查并用当前失败样本证明能失败，再修实现。

## 坐标与实现门禁

- 先固定父节点源画框，再用 `child.bounds - parent.bounds` 计算局部坐标。禁止移动父节点来补偿子节点误差。
- 蒙版、圆角、边框、渐变、阴影和裁剪分别映射；不能用一个近似 `BoxDecoration` 概括多个源层。
- 对每个效果保留节点 ID 与源参数到代码常量或生成数据的映射。框架单位与源/CSS 单位存在差异时，记录校准依据并用局部效果检查验证。

## 轮次与停止门禁

目标流程是一次完整取证、一次集中实现和 1–2 次批量修正：

1. **R1 完整性轮**：首先验证有无漏节点、缺字体、缺素材和父级几何错误，再看细节像素。
2. **R2 批量修正轮**：按根因一次修完同类几何、字体、素材或效果问题。
3. **R3 收尾轮**：处理少量残差并做最终并列复查。

第三轮仍有明显缺失、blocking failure 或未处理节点时，状态保持未完成；切换到定向 inspect、原始导出、render fallback 或占位策略。不得因为达到三轮而交付，也不得重置日志。连续两轮同类指标无改善时停止微调，回到证据和坐标模型重新定位。

## 交付定义

只有同时满足以下条件才能将结果称为高保真验收结果：

- 可见节点处置闭环，`unaccounted_visible_nodes = 0`；
- v2 契约全部 blocking 检查通过，或仅有逐项披露的素材排除；
- 最终原稿/实现并列图没有明显漏层；
- 可运行页面、功能测试、静态检查和目标平台构建通过；
- 日志显示真实轮数、重试、总等待时间和仍存在的排除项。

任一条件不满足时可以提供“诊断预览”，但标题、日志和回复都必须明确标为未完成，不能描述为最终还原结果。
